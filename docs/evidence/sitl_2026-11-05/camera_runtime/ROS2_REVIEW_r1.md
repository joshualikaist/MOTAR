## Main source checks

- RGB/BGR row padding, endian depth decoding, millimetres/metres and independent zero/nonfinite invalid masks are handled explicitly. Rectified CameraInfo.P supplies pixel intrinsics; unsupported binning/ROI, nonidentity rectification rotations, stereo optical-center offsets and changing calibration reject. Declared measured extrinsics convert optical right/down/forward into camera-FLU before the unchanged body-to-yaw projection. Calibration evidence is path/SHA-bound at initialization; this validates a binding, not the physical correctness of supplied measurements.
- Odometry pose uses header/world ENU and twist uses child/body FLU, with one body-to-world rotation for velocity. This matches the primary [Humble Odometry definition](https://raw.githubusercontent.com/ros2/common_interfaces/humble/nav_msgs/msg/Odometry.msg) and [REP103 conventions](https://raw.githubusercontent.com/ros-infrastructure/rep/master/rep-0103.rst). Original acquisition stamps are retained, not replaced by callback time. All four selected inputs must meet25ms skew and150ms capture/receipt age bounds, advance beyond the last used samples and use declared frames/clock conventions.
- Session callbacks and prepare/finish belong to the serialized executor; one worker performs inference. Epoch/fault latches discard late or revoked work. Runtime invalidation is deferred while a worker may mutate Torch history, then applied after completion. Reset is refused while work remains active. Clock pause/regression, output/input staleness and control-period violations latch the session. Output TwistStamped retains the oldest selected capture stamp. Proposed velocity is explicitly ENU and no vehicle command is sent by the policy node.
- PX4 decoding requires NED pose/velocity and FRD angular rates, validity/reset counters and fresh sample/publication/receipt timestamps. NED/FRD->ENU/FLU conversion and ENU->NED command signs are consistent. I checked local primary PX4 source: VehicleStatus POSCTL=2, AUTO_MISSION=3, OFFBOARD=14; `Tools/msg/templates/ucdr/msg.h.em` translates both timestamp and timestamp_sample, and uXRCE serialization receives the agent time offset. No second boot-clock offset is invented.
- The independent bridge defaults to observation only. Enabled publication additionally needs a bound flight-check file and an explicit prime service. There is no VehicleCommand arm/takeoff/mode path. Priming, ACTIVE ownership, mode/disarm/failsafe loss, clock discontinuities, estimator reset and stale/duplicate policy/telemetry cause latched revocation. Reset stops derived odometry before a rebased pose reaches old policy history. Restart/reset is explicit; no automatic re-entry is present.
- Typed PX4 input definitions are SHA-bound to local v1.14.3; the wrapper verifies the installed package share definitions and generated field/type shape before publisher creation. Both outgoing typed messages are constructed before either publish. Partial DDS publication cannot be atomic; exceptions revoke future streams. Publisher depth1/volatile/lifespan150ms reduces retention; it does not establish end-to-end delivery or a physical expiry guarantee.
- Ament package entry and launch require explicit source/config paths. Templates remain UNCONFIGURED with no invented mount, alignment, policy path, firmware provenance or enabled offboard publication. Import and metadata-check paths remain free of graph/device/policy construction. Package documentation separates proposals from physical readiness and identifies the Python3.8 policy versus Humble/Python3.10 ABI gap.

## Practical limits

There is no installed/executed ROS graph here and no real CameraInfo, OAK alignment/mount record, PX4 clock/firmware/DDS/vehicle binding or flight-check evidence. The generated-type validator was exercised with source-shaped fakes; actual installed rclpy/px4_msgs API execution remains NOT_TESTED. Ament install/colcon build and a compatible ROS/PyTorch Python environment remain outstanding. The camera producer must provide acquisition-stamped calibration on the RGB grid; ordinary latched/zero-stamped CameraInfo is deliberately unsupported. A separate qualified position estimator is still required.

Deadline handling is cooperative software rejection. A hung inference thread may require a process supervisor; process shutdown/OS scheduling/transport blocking are not hard real-time guarantees. The independent gateway must qualify its actual DDS/offboard-loss response; stopping streams is not a hover/landing guarantee. A single qualified vehicle/domain and exclusive offboard ownership are assumed; DDS topics are not MAVLink source-ID attribution. Metadata hashing does not certify a flight-check file's contents. Bootstrap red target appearance, physical sensor equivalence, tracking/capture, vehicle dynamics, ground handling, takeover and flight readiness are unqualified.

관련: `docs/sim_vs_hardware_gap_2026-08.md`(격차 측정), Codex 검증 5 사전등록(브리프 #3 §3)

## 0. 세 줄 요약

1. 현재 URDF는 **자기모순**이다 — 관성은 18 cm 기체, 충돌박스는 28 cm 기체.
   즉 "generic quad를 상속하고 충돌 기하만 키운" 상태이며, 어떤 실제 빌드와도 대응하지 않는다.
2. 현실 5인치급으로 맞추면 **병진 기동은 그대로**(수평가속 9.8 m/s², 질량 무관),
   충돌폭도 28→32 cm로 **4 cm만 증가**(막대 간극 160 cm 대비 여유 82%→80%).
   각가속만 4배 둔해지고 모터 응답이 2배 느려진다.
3. **결론: 예상보다 훨씬 값싼 수정이다.** 성능 급락 위험은 낮고, 얻는 것은 "실제로 존재하는
   기체"라는 하드웨어 신뢰도다.

## 1. 현재 상태 진단

| 항목 | 값 | 출처 | 문제 |
|---|---|---|---|
| 질량 | 225 g + 로터 25 g = **250 g** | Aerial Gym `quad.urdf` **기본값 그대로** | 선택된 값이 아님 |
| 모터 추력 | 2 N × 4 = 8 N | `base_quad_config` **기본값** | 선택된 값이 아님 |
| 모터 위치 | ±0.065 m → 반경 9.2 cm, **대각 18 cm** | URDF | — |
| 충돌 박스 | **28 cm** | 07-22에 **의도적으로 변경**(0.05 m 구 → 0.28 m 박스) | 모터 배치(18 cm)와 1.5배 불일치 |
| 관성 ixx | 4.23e-4 | 기본값 | 28 cm 균일박스 근사(1.77e-3) 대비 **4.2배 작음** |
| 각가속 | ≈870 rad/s² | 계산 | 비현실적으로 큼 |

**핵심**: 충돌 기하만 보수적으로 키우고 질량·관성·추력은 프레임워크 기본값을 상속했다.
그 결과 **"18 cm 기체의 회전 민첩성 + 28 cm 기체의 충돌 단면"** 이라는 조합이 되었다.
전자는 낙관적, 후자는 보수적이라 서로 상쇄되지만, 어느 실제 기체도 아니다.

## 2. 제안: 5인치급 기준 플랫폼

우리 인지 스택(Orin NX 100 g + Livox Mid-360 265 g + RealSense 72 g + Pixhawk 35 g = **472 g**)을
실을 수 있는 최소 현실 빌드.

| 파라미터 | 현재 | **제안** | 근거 |
|---|---:|---:|---|
| 총 질량 | 0.250 kg | **1.20 kg** | 프레임/배터리/모터 ~730 g + 페이로드 472 g |
| 모터 추력(개당) | 2.0 N | **9.6 N** | T/W 3.26 **유지**(5인치 모터 실측 1 kgf급과 일치) |
| 모터 반경 | 0.065 m | **0.125 m** | 대각 25 cm = 5인치 표준 프레임 |
| 충돌 박스 | 0.28 m | **0.32 m** | 프로펠러 포함 실폭 |
| 관성 ixx=iyy | 4.23e-4 | **1.12e-2** | 균일 박스 근사 m(w²+h²)/12 |
| 관성 izz | 8.45e-4 | **2.05e-2** | 동상 |
| 모터 시상수 | 0.04 s | **0.08 s** | 5인치 프로펠러 관성 |
| 최대 틸트 | 45° | 45° (유지) | — |
| v_max / yaw rate | 2.5 / 2.5 | 유지 | 관측 계약 불변 |

### 무엇이 바뀌고 무엇이 안 바뀌나

| 성능 지표 | 현재 | 제안 | 변화 |
|---|---:|---:|---|
| **수평 가속** | 9.8 m/s² | 9.8 m/s² | **불변** (= g·tan45°, 질량 무관) |
| **상승 가속** | 22.2 m/s² | 22.2 m/s² | **불변** (T/W 유지) |
| 각가속도 | 870 rad/s² | 213 rad/s² | **0.25배** |
| 모터 응답 | 40 ms | 80 ms | 2배 느림 |
| 충돌폭 | 28 cm | 32 cm | **+4 cm** |
| 막대 간극(160 cm) 대비 여유 | 82% | 80% | **−2%p** |

**병진 기동이 불변**이라는 것이 이 수정안의 핵심이다. 정책이 실제로 쓰는 행동(속도 명령)의
물리적 한계가 그대로이므로, 성능 급락 위험이 낮다. 나빠지는 것은 **회전 민첩성과 제동 응답**
이며, 이는 검증 4가 지목한 stopping-margin 문제와 **같은 축**이라 오히려 측정 가치가 있다.

## 3. 검증 5 사전등록 수정안

Codex 사전등록 순서(①스모크 → ②baseline → ③v7 → ④envelope)를 **유지**하되, ②의 기체
파라미터를 기준 플랫폼으로 교체한다.

**변경 범위**: URDF 1개 신규(`quad_navrl_ref5in.urdf`) + robot_config 1개 신규 +
task_config의 `robot_name` 1줄. **코드 변경 없음.**

**필수 선행 검증(GPU 불필요, 각 수 분)**:
1. URDF 자기일관성 — 관성이 질량·기하와 맞는지 단위테스트(현재의 4.2배 불일치가 재발하지 않게)
2. 호버 검증 — 제어기가 새 질량에서 호버 추력을 내는지(T/W 3.26이면 정상)
3. 스텝 응답 — 속도 명령 2.5 m/s에 대한 정착 시간이 모터 τ 0.08 s와 정합하는지
4. 아레나 배치 가능성 — 충돌폭 32 cm에서 navrl_band 배치가 여전히 slit-불가능한지

**제안 arm 구조**(기존 계보 보존):

| arm | 기체 | 검출기 | 목적 |
|---|---|---|---|
| ②-legacy | 현재 250 g | analytic | 기존 계보와의 연속성(선택) |
| **②-ref** | **기준 5인치** | analytic | **새 본선 baseline** |
| ③ | 기준 5인치 | v7 | 검출기 결합 |
| ④ | 기준 5인치 | v7 + envelope | 외형 강건 |

**주의**: ②-legacy와 ②-ref는 **기체가 다르므로 비교 불가**다(v1↔v2 task-version bump와 동일
원칙). 논문에는 ref 계보를 본문, legacy를 방법론 개발 이력으로 쓴다.

## 4. 소요 시간 추정

### (A) 기체 파라미터만 교체하는 최소안

| 단계 | 작업 | 소요 |
|---|---|---|
| 1 | URDF + robot_config 작성, 관성 일관성 테스트 | **2~3시간** |
| 2 | 호버/스텝응답/배치가능성 검증 (GPU 짧게) | **1시간** |
| 3 | 학습 스모크 500 epoch (발산·NaN 확인) | **1~2시간** |
| 4 | **본 학습** ②-ref (fresh, 커리큘럼 70→205) | **3~5일** |
| 5 | held-out 평가 + WORKLOG/커밋 | **半일** |
| | **합계** | **약 4~6일** (대부분 4번) |

학습 시간 근거: 기존 v2 계보가 fresh 70→205 커리큘럼에 약 24,000 epoch 소요됐고
(07-31 시작 → 08-02 205막대 도달, 실측 ~2.5일), 여기에 안전 여유를 더한 값.
**시드 1개 기준**이며, Codex 검수가 권고한 "주장하려면 시드 2~3개"를 따르면 **×2~3**.

### (B) 검증 5 전체(Codex 사전등록 4단계)를 기준 플랫폼으로

| 단계 | 소요 |
|---|---|
| ①스모크 (500~1,000 epoch) | 0.5일 |
| ②-ref baseline 본학습 | 3~5일 |
| ③ v7 arm (같은 예산) | 3~5일 |
| ④ envelope arm (같은 예산) | 3~5일 |
| 각 arm 평가 + 기록 | 1일 |
| | **합계 약 11~17일** (시드 1개) |

시드 3개로 가면 **1개월+**. GPU가 1대이므로 순차 실행 기준이다.

### (C) 권고 — 단계적 결정

```
지금 ─┬─ (0) 기체 파라미터 작성 + 정합성 검증 ............ 3~4시간
      └─ (1) 스모크로 학습 가능성만 확인 ................. 1~2시간
                    ↓ 여기서 판단
      ┌─ 정상이면 → ②-ref 본학습 시작 (3~5일)
      └─ 문제면 → 파라미터 조정 후 재스모크
```

**(0)+(1)만 먼저 하는 것을 권합니다** — 반나절이면 "이 기체로 학습이 되는가"가 판명되고,
안 되면 본학습 3~5일을 낭비하지 않습니다. 그 결과를 보고 검증 5 전체 계획을 확정하면 됩니다.

## 5. 하지 않기로 한 것 (근거 명시)

- **충돌박스만 키운 민감도 스윕**(0.28→0.35→0.45 eval-only): 계산해 보니 현실 플랫폼의
  충돌폭이 32 cm로 **현재와 4 cm 차이**라, 스윕의 정보 가치가 예상보다 작다. 기체 전체를
  현실화하는 편이 낫다. (단, 본학습이 부담되면 이 eval-only 스윕이 여전히 최저비용 대안이다.)
- **7인치급 이상**: 페이로드 472 g은 5인치로 충분하며, 크게 갈수록 간극 여유가 급감한다.
- **LiDAR 제거(D8)와 동시 진행**: 변수 2개 중첩 — 기체 현실화가 먼저, 센서 경량화는 그다음.
